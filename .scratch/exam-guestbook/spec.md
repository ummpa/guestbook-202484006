# Spec: 맛집 방명록 (실기시험 버전)

Status: done

## Problem Statement

전국 식당을 다니며 맛있었던 곳을 누구나 가입 없이 바로 남기고, 모두가 최신순으로 읽을 수 있는 가벼운 방명록이 필요하다. 계정이 없으므로 글쓴이 본인만 자기 글을 고치거나 지울 수 있게 할 다른 방법이 필요하다.

## Solution

한 페이지짜리 방명록. 위쪽 폼에서 이름·글 비밀번호·식당 이름·지역·별점·메시지를 입력해 글을 남기고, 아래 목록에서 모든 글을 최신 작성 순으로 본다. 각 글의 "수정"은 글 비밀번호를 입력해야 메시지를 바꿀 수 있고, "삭제"도 글 비밀번호를 입력해야 글을 지울 수 있다. 비밀번호가 틀리면 거부되고 "비밀번호가 일치하지 않습니다."가 표시된다. 머리글과 바닥글에 개발자 이름과 학번을 표시한다.

## User Stories

1. 방문자로서, 가입 없이 이름·메시지·글 비밀번호를 입력해 글을 남기고 싶다.
2. 방문자로서, 글에 식당 이름·지역(시/도)·별점(1~5)을 함께 남기고 싶다. 그래야 어떤 식당을 추천하는지 알 수 있다.
3. 방문자로서, 입력이 잘못되면(빈 칸, 길이 초과) 이유를 안내받고, 쓴 내용은 폼에 남아 있으면 좋겠다.
4. 방문자로서, 글을 남기면 폼이 비워지고 목록 맨 위에 내 글이 보이면 좋겠다.
5. 방문자로서, 전체 글 목록을 최신 작성 순으로 보고 싶다.
6. 방문자로서, 글마다 이름·식당·지역·별점·메시지·작성 시각을 보고 싶다.
7. 방문자로서, 수정된 글은 수정 시각과 함께 "수정됨"으로 보고 싶다.
8. 글쓴이로서, 글 비밀번호를 입력해 내 글의 메시지를 고치고 싶다.
9. 글쓴이로서, 비밀번호가 틀리면 수정이 거부되고 그 사실을 안내받고 싶다.
10. 글쓴이로서, 글 비밀번호를 입력해 내 글을 지우고 싶다.
11. 글쓴이로서, 비밀번호가 틀리면 삭제가 거부되고 그 사실을 안내받고 싶다.
12. 방문자로서, 다른 사람이 내 글 비밀번호를 볼 수 없으면 좋겠다.
13. 채점자로서, 화면에서 개발자 이름과 학번을 확인하고 싶다.

## Implementation Decisions

- 방명록 모듈 하나(DB와 현재 시각을 주입받음): 글 작성, 목록(최신순), 메시지 수정(비밀번호 확인), 글 삭제(비밀번호 확인). 결과는 성공 여부 + 실패 사유 코드로 돌려준다.
- 테이블 하나: 이름, 식당, 지역(17개 시/도 체크 제약), 별점(1~5 체크 제약), 메시지, 글 비밀번호 해시(scrypt + salt), 작성 시각, 수정 시각.
- 입력 제한: 이름 1~20자, 식당 1~50자, 메시지 1~500자, 글 비밀번호 4~30자. 앞뒤 공백 제거.
- 수정은 메시지만 가능. 수정해도 목록 순서(작성 시각)는 그대로.
- 화면은 Server Actions + useActionState. 수정·삭제는 글마다 펼쳐지는 비밀번호 입력 폼.
- Next.js 16(App Router) + TypeScript, Neon Postgres, Vercel 배포.

## Testing Decisions

- 방명록 모듈의 공개 함수만 호출해 동작을 확인한다. PGlite에 실제 스키마를 적용한 DB를 테스트마다 새로 만든다.
- 작성 검증과 경계값, 비밀번호 비노출, 최신순, 올바른/틀린 비밀번호로 수정·삭제, 다른 글 비밀번호 거부, 없는 글.

## Out of Scope

- 회원 가입·로그인, 운영자, 식당별 모아 보기·평균 별점·지역 필터, 페이지 나누기, 비밀번호 찾기.
