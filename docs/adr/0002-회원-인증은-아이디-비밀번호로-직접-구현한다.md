# 회원 인증은 아이디·비밀번호로 직접 구현한다

회원 가입과 로그인은 Auth.js·소셜 로그인 없이 아이디와 비밀번호로 직접 구현한다. 비밀번호는 해시로만 저장하고 로그인 상태는 세션 쿠키로 유지한다. 수업 과제로서 인증 흐름 자체를 보여 주고, OAuth 앱 등록이나 외부 키 없이 동작하게 하기 위해서다. 그만큼 비밀번호 해싱, 세션 만료, 쿠키 설정 같은 보안 책임을 직접 진다.

운영자는 회원 계정이 아니라 환경변수에 둔 운영자 비밀번호 하나로 따로 들어온다. 그래서 로그인 경로가 두 개(회원·운영자)다.

## Considered Options

- 소셜 로그인(Auth.js + 구글/카카오/GitHub): 비밀번호를 저장하지 않아도 되지만 OAuth 설정과 외부 의존이 생긴다.
- 운영자를 회원 중 일부로 지정: 로그인 방식이 하나로 줄지만, 운영자 역할을 별도 비밀번호로 분리하는 쪽을 택했다.
