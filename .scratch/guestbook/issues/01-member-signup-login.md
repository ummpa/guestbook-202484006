# 01: 회원 가입·로그인·로그아웃 (tracer bullet)

**What to build:** 방문자가 `/signup`에서 아이디·비밀번호·비밀번호 확인·닉네임을 입력해 회원이 되면 바로 로그인된 상태가 되고, 모든 화면 머리글에 닉네임과 로그아웃 버튼이 보인다. `/login`에서 아이디·비밀번호로 로그인하면 7일 동안 유지되며, 로그아웃하면 즉시 풀린다. 이 티켓이 이후 모든 티켓의 기반을 깐다: 전체 스키마(회원·세션·식당·글), 스키마 적용 스크립트, DB 어댑터(운영 Neon / 테스트 PGlite), Vitest+PGlite 테스트 환경, 인증 모듈 전체, 따뜻한 음식 테마의 기본 레이아웃. 그리고 이 상태로 Vercel에 한 번 배포해 배포 경로를 먼저 연다. 스펙: `.scratch/guestbook/spec.md` (용어: GLOSSARY.md, 결정: ADR 0002).

**Blocked by:** None (can start immediately)

**Status:** wontfix (ADR-0003으로 대체됨)

- [ ] 스키마 SQL 파일에 회원·세션·식당·글 테이블이 모두 있다: 아이디·닉네임 유일, 별점 1~5 체크, 지역 17개 시/도 체크, (식당 ID, 작성자 회원 ID) 유일, 식당 삭제 시 글 cascade
- [ ] 스크립트 하나로 스키마가 Neon에 적용된다
- [ ] 도메인 모듈은 "매개변수 있는 SQL 한 문장 실행" 인터페이스와 현재 시각 함수만 주입받는다. 운영은 Neon, 테스트는 PGlite 구현을 쓴다
- [ ] 테스트 명령 하나로 Vitest가 PGlite 위에서 실행된다(네트워크 불필요, 테스트마다 격리된 DB, 실제 스키마 적용)
- [ ] 가입 검증: 아이디 4~20자 `[a-z0-9_]`, 비밀번호 8~64자, 닉네임 1~20자(앞뒤 공백 제거 후), 비밀번호 확인 일치. 실패 시 구체적 실패 사유를 돌려준다
- [ ] 아이디 중복·닉네임 중복은 각각의 실패 사유로 거절되며, 동시 가입으로 인한 DB 유일 제약 위반도 같은 사유로 바뀐다
- [ ] 비밀번호는 salt를 포함한 scrypt 해시로만 저장되고 시간 일정 비교로 확인된다
- [ ] 로그인 실패는 없는 아이디와 틀린 비밀번호를 구분하지 않는다
- [ ] 세션 토큰은 추측 불가 무작위 값이고 DB에는 해시만 저장되며, 만료는 발급 후 7일로 서버에서도 확인된다
- [ ] 세션 쿠키: HttpOnly, SameSite=Lax, 운영에서 Secure, 7일
- [ ] 로그아웃하면 세션이 폐기되어 같은 토큰으로 더 이상 회원이 조회되지 않는다
- [ ] 가입 폼은 규칙과 "닉네임은 바꿀 수 없다" 안내를 보여 주고, 거절 시 비밀번호를 제외한 입력값을 유지한다
- [ ] 로그인한 회원이 `/signup`·`/login`에 들어가면 `/`로 보내진다
- [ ] 로그인 후 돌아갈 주소(앱 내부 경로만 허용)를 받을 수 있다
- [ ] 기본 레이아웃: 크림색 배경·주황 포인트, 모바일 우선, 머리글(앱 이름, 로그인 상태에 따라 로그인/가입 또는 닉네임/로그아웃)
- [ ] 운영자 비밀번호 확인 함수(환경변수와 비교)가 인증 모듈에 있다(화면은 06)
- [ ] Vercel에 배포되어 운영 URL에서 가입·로그인·로그아웃이 동작한다. 필요한 환경변수(DB 주소, 운영자 비밀번호, 쿠키 서명 비밀값)가 README에 적혀 있다
- [ ] 인증 모듈 테스트: 가입 검증 실패 사유들, 아이디 중복, 닉네임 중복, 가입·로그인 토큰으로 회원 조회, 틀린 비밀번호와 없는 아이디가 같은 사유, 7일 지난 세션은 회원 없음(주입 시각 이동), 로그아웃한 토큰은 회원 없음, 운영자 비밀번호 일치·불일치
